# Формат сейва RSE1

Разбор выполнен на предоставленном `.sav` и `C:\WoW\Surv\AzerothSurvivors.exe` от 18 октября 2026 года. Это отдельная игра на Rust/Bevy с данными WoW 1.12.1, не аддон WoW 3.3.5a. MPQ содержат ресурсы мира; формат сохранения реализован в `.exe`.

## Контейнер

```text
RSE1: + Base64(nonce[16] || ciphertext[N] || tag[20])
```

- `ciphertext` — UTF-8 текст, XOR с потоком 20-байтных блоков.
- Блок `i` равен `HMAC-SHA1(key, "ks" || nonce || uint64_le(i))`.
- `tag` равен `HMAC-SHA1(key, "tag" || nonce || ciphertext)`.
- Ключ восстановлен из бинарника и хранится в [codec.js](../src/codec.js). Он нужен для совместимости, это не пользовательский пароль.

Подпись исходного файла совпала с расчётом, расшифрованный текст начинается со строки `pick|…`. Экспорт повторно запечатывается со случайным nonce и новой подписью. Тест на чтение нового файла собственным декодером подтверждает обратимость алгоритма; это не доказывает, что игра принимает любую изменённую игровую семантику.

## Очки талантов

Код текущего исполняемого файла выдаёт до 51 очка за суммарный опыт класса. Первое очко стоит 80 XP, каждое следующее — на 15 XP больше: 80, 95, 110 и т. д. Порог для `n` очков равен `80n + 15n(n-1)/2`; для 51 очка это 23 205 XP. Редактор вычисляет полученные очки из сохранённого опыта, потраченные — как сумму рангов, свободные — как разность. Если сумма рангов превышает заработанные очки, редактор предупреждает об этом, но не удаляет значения из сейва.

`data/game.json` содержит порядок трёх веток каждого класса, названия всех 354 талантов и доступные описания из текущего `.exe`. Сохранение хранит только суммарный опыт и пары `id:rank`; ограничения рангов и расположение узлов в игровом дереве редактор не навязывает. В описаниях `…` заменяет игровую переменную `{v}`, значение которой зависит от ранга. Отсутствующие точные иконки заменяются значком ветки или класса.

## Иконки

`data/game.json`, `data/visuals.json`, `assets/icons/game/` и `assets/icons/game-atlas.png` создаются `tools/build_visuals.py`. Сайт загружает иконки из одного атласа. Порядок 102 легендарных амулетов по классам, тексты 63 достижений и названия иконок кодекса извлечены из таблиц текущего `.exe`. Для комплектов брони использованы названия наборов из `.exe` и иконки соответствующих предметов WoW Classic. Иконки стартового и PvP-наборов, а также части оружия и заклинаний являются визуальным приближением, поскольку их точное соответствие нельзя установить по предоставленному сейву. Каталог изображений не участвует в чтении или записи RSE1.

## Строки, найденные в образце

| Строка | Наблюдаемое содержимое |
| --- | --- |
| `pick` | Выбор героя, класса, расы, зоны и вид. |
| `open` | Открытая зона для класса. |
| `beat` | Список пройденных зон класса. |
| `talent` | Опыт талантов и пары `id:rank` класса. |
| `items` | Числовые ID найденных предметов аккаунта. |
| `equip` | Пары `slot:item_id` для класса. |
| `look` | Внешний вид экипировки класса. |
| `seen` | Пары `id=quality` кодекса (качество от 0 до 4 в образце). |
| `ach` | ID достижений аккаунта. |
| `achat` | Время получения достижений (Unix seconds). |
| `stat` | Счётчики аккаунта. |
| `perk` | Пары `id:rank` бонусов. |
| `pets` | ID открытых спутников. |
| `hero` | Выбор героя по классу. |

Программа меняет только выбранные строки и сохраняет незнакомые записи. Каталог 354 ID талантов извлечён из структур текущего `.exe`; каталог достижений дополнен ключами из него. Каталог предметов и кодекса основан на предоставленном сейве и ключе `Shred`, подтверждённом скриншотом игры. Другие ID можно ввести вручную, но игру нужно использовать для проверки их допустимости. Значение `open` не автоматически выводится из `beat`; редактор оставляет пользователю оба поля.

Предметы в образце используют шестизначную схему `1CCSR0`: `CC` — ID класса, `S` — ячейка, `R` — комплект. Найденные значения `R=0..4` соответствуют обычному, необычному, редкому, эпическому и легендарному наборам. Дополнительный PvP-набор в интерфейсе игры доступен отдельно; редактор показывает выведенные по этой схеме ID с `R=5` неотмеченными. Эти ID пока не подтверждены импортом конкретного PvP-предмета. Добавление `legendary:shred=4` в `seen` пользователь подтвердил в игре.
